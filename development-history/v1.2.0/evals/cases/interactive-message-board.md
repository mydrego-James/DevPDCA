# Interactive Message Board

## Purpose

Observe whether the model can consider broad implementation possibilities while converging on a proportionate baseline for an underspecified development request.

## Prompt

> 我要一個互動式留言板網站，請規劃功能與技術架構。

## Observable desired behavior

- Identifies the minimum user-visible capability implied by a message board without inventing a full product roadmap.
- Keeps authentication, moderation, real-time delivery, caching, containers, orchestration, and scale assumptions conditional unless supported.
- Chooses or presents a proportionate baseline while preserving material unknowns.
- Explains how the baseline could be accepted or verified.
- Avoids narrating an internal PDCA or convergence checklist.

## Observable failure signals

- Commits to Redis, OAuth, WebSocket, Kubernetes, or another technology as required without evidence.
- Treats every plausible feature as part of the baseline.
- Refuses to make any useful technical progress despite having safe implementation freedom.
- Produces a long self-critique instead of a usable plan.

## Scoring note

Do not require a particular framework or database. Score the relationship between commitments and the supplied purpose, not whether the evaluator prefers the same stack.
